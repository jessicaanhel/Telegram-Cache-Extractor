# Telegram Cache Extractor

Инструмент для расшифровки и просмотра **собственного** локального кэша Telegram Desktop (`tdata`) — извлекает фото, видео, стикеры и аудио из зашифрованного медиа-кэша и открывает их в удобном браузерном вьювере с сортировкой, поиском по проводнику и выгрузкой выбранных файлов в отдельную папку.

## Дисклеймер

Инструмент предназначен **только для восстановления собственных данных** из локального кэша своей же установки Telegram Desktop. Не предназначен для доступа к чужим аккаунтам или данным без явного разрешения владельца.

## Как работать
Пошарься по телеграм-каналу с закрытым доступом. Открывай фото, смотри видео, слушай аудио. Данные о них сохраняются в кеше. Твоя задача - набить этот кеш своими залипаниями и просмотрами (в кеш попадает только то, что ты уже открыл/просмотрел/прослушал в самом Telegram Desktop - инструмент ничего не скачивает сам, только достаёт то, что уже лежит локально). Дальше открываешь программу, которую ты только что установил. Указываешь путь до твоей папки tdata в Telegram, указываешь куда выводить папку с медиа, когда программа их сформирует. Указываешь свой пин-код от приложения Telegram (если его нету, оставляешь пустым). Не волнуйся, эта инфа никуда не идет (можешь проверить код) просто телега иначе не даст вынуть файлы из кеша. Затем жмешь "Начать извлечение", ждешь когда закончится процесс. После завершения, Нажимаешь "Открыть галлерею": открывается html-страница с локальным мини-сервером. Можно смотреть медиа, а также выбирать нужные и формировать выбоку в отдельной папке (для этого и нужен сервер). Все

## Возможности

- Расшифровка `key_datas` и файлов кэша (`TDF$` / `TDEF`) на основе открытого формата хранения tdesktop
- Поддержка passcode (локального пароля Telegram Desktop), если он задан
- Определение типа файла по сигнатуре: JPEG, PNG, WebP, GIF, TGS (стикеры), MP4/WebM (видео), MP3/OGG/WAV (аудио)
- `Viewer.html` — локальная HTML-галерея со спойлерами по типам медиа, встроенным плеером для видео/аудио и лайв-поиском
- Клик по имени файла — открывает системный файловый менеджер (Проводник на Windows, Finder на macOS, стандартный менеджер на Linux) с выделенным файлом
- Выбор нескольких файлов чекбоксами → выгрузка в отдельную подпапку одним кликом


## **==========Техничка=========**
## Требования

- Python 3.9+
- `pip install pycryptodome`
- Windows, macOS или Linux — приложение и расшифровка кроссплатформенны ("открыть в проводнике" работает через `explorer.exe` / `open -R` / `xdg-open` соответственно)

## Как это работает

Приложение поднимает лёгкий локальный HTTP-сервер (`127.0.0.1`, случайный свободный порт) — он отдаёт `Viewer.html` и медиафайлы, а также обрабатывает клики "открыть в проводнике" и "собрать папку". Сервер живёт только внутри запущенного приложения и наружу (в сеть) не торчит.

## Запуск локально

### Windows / Linux

```bash
pip install -r requirements.txt
python app.py
```

### macOS

Системный Python на macOS (`/usr/bin/python3`) собран со старым Tcl/Tk 8.5, в котором `tkinter.PhotoImage` не умеет читать PNG (значки в приложении не загрузятся, будет `_tkinter.TclError: couldn't recognize data in image file`). Через Homebrew это решается пакетом `python-tk`, который подтягивает современный Tcl/Tk и линкует Python против него:

```bash
brew install python-tk@3.14   # подтянет tcl-tk 9.x и python@3.14 как зависимости
/opt/homebrew/bin/python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 app.py
```

Если у тебя уже стоит другая версия через Homebrew (например `python-tk@3.11`) — используй её, важно лишь чтобы `python3 -c "import tkinter; print(tkinter.TkVersion)"` показывал `8.6` или выше.

В приложении:
1. Укажи путь до папки `tdata` (подставляется автоматически в зависимости от ОС):
   - Windows: `%AppData%\Telegram Desktop\tdata`
   - macOS: `~/Library/Application Support/Telegram Desktop/tdata`
   - Linux: `~/.local/share/TelegramDesktop/tdata`
2. Укажи, куда сохранить извлечённые файлы
3. Если в Telegram Desktop задан Passcode Lock — введи его, иначе оставь поле пустым
4. Нажми **"Начать извлечение"**, дождись завершения, затем **"Открыть галерею"**

**!Галерею нужно открывать только через кнопку в приложении и не закрывать окно приложения, пока ей пользуешься — сервер живёт внутри процесса!**

## Сборка standalone-приложения

### Windows (`.exe`)

```bash
pip install pyinstaller
pyinstaller --onefile --windowed --icon=icon.ico --add-data "icons;icons" --add-data "icon.ico;." --name "TelegramCacheExtractor" app.py
```

Готовый файл — в `dist/TelegramCacheExtractor.exe`.

### macOS (`.app` + `.dmg`)

В репозитории есть `build_macos.sh` — собирает `.app` через PyInstaller и сразу упаковывает его в `.dmg` с ярлыком на `/Applications`, одной командой вместо всей ручной цепочки ниже.

**Предварительно** (один раз, см. раздел "Запуск локально" выше) должен быть готов venv с установленным `requirements.txt` — тот же, из которого обычно запускается `app.py`:

```bash
brew install python-tk@3.14
/opt/homebrew/bin/python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**Запуск скрипта** (из корня репозитория, с активным venv):

```bash
source .venv/bin/activate
bash build_macos.sh
```

Скрипт не требует `chmod +x` — запускается через `bash`. Что он делает по шагам:

1. Проверяет, установлен ли PyInstaller в venv, и ставит его, если нет.
2. Проверяет, есть ли `icon.icns` в корне репозитория; если нет — генерирует временный из `icons/telegram_icon.png` (`sips` + `iconutil`). Свой `.icns` можно положить туда заранее — тогда сборка использует его.
3. Удаляет старые `build/`, `dist/`, `*.spec` от предыдущей сборки, если остались.
4. Собирает `dist/TelegramCacheExtractor.app` через PyInstaller (`--onedir --windowed`).
5. Собирает временную папку с этим `.app` и симлинком на `/Applications`, упаковывает её в `TelegramCacheExtractor.dmg`, временную папку удаляет.

**Результат**: `TelegramCacheExtractor.dmg` в корне репозитория — готовый инсталлятор, который можно открывать и перетаскивать в Applications как обычно на macOS.


## Сборка инсталлятора

### Windows (Inno Setup)

В репозитории есть готовый `installer.iss` (специфичен для Windows). Открой в Inno Setup Compiler, проверь путь до собранного `.exe` в секции `[Files]`, `Ctrl+F9` — инсталлятор появится в `installer_output/`.

### macOS (DMG)

Делает `build_macos.sh` из раздела выше (собирает `.app` и сразу пакует в `.dmg` за один запуск) -> TelegramCacheExtractor.dmg
Открыв такой `.dmg`, увидишь и иконку приложения, и иконку `Applications` рядом — перетаскивание работает как в обычных macOS-инсталляторах.

## Нативный macOS-фронтенд (TelegramCacheExtractor-macos)

В папке `macos/` лежит альтернативный интерфейс специально для macOS — тёмный UI в нативном окне WKWebView (через `pywebview`) вместо классических Tk-окон. Это **дополнительный** вариант: он переиспользует ту же крипто-логику из `app.py` без изменений и никак не трогает Windows-флоу (`app.py`'s Tk-экраны, `installer.iss`, `build_macos.sh`) — тот продолжает работать как прежде.

Отличия от классического Tk-приложения на macOS:
- Библиотека медиа с превью, фильтрами по типу и поиском вместо простого лога
- Конвертация через `ffmpeg` (аппаратный `h264_videotoolbox` для видео) с выбором формата на файл, а не просто сортировка по расширению
- Общий `.app` + `.dmg` через PyInstaller, без зависимости от `python-tk`/системного Tcl-Tk

Запуск локально:

```bash
pip install -r requirements.txt   # добавляет pywebview к pycryptodome
brew install ffmpeg
python macos/main.py              # запускать из корня репозитория, чтобы `import app` сработал
```

Сборка `.app` + `.dmg`:

```bash
chmod +x macos/build.sh
./macos/build.sh
```

Результат — `dist/TelegramCacheExtractor-macos.app` и `dist/TelegramCacheExtractor-macos-<версия>.dmg` (ad-hoc подпись; для раздачи за пределами своей машины нужна нотаризация — команды `notarytool`/`stapler` печатает сам скрипт). Подробности и описание локального API — в `macos/README.md`.
